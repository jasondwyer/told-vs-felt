## §2 The stored-text invariant (gcal read §4 O5)

**2.1 The defect.** `OLMoHFAdapter.generate` checks `_is_stop` (`valence_core/adapters/olmo_hf.py:290–294`) before it sets `content_seen` (`:251`/`:256` on the cached path, `:274`/`:279` on the uncached), and `_is_stop` fires on a token containing `\n` only once `content_seen` is true; a *first* token that carries content and a newline together (`---\n\n`) is therefore appended, and generation runs to a later newline. Two G-CAL-OLMo generations stored text with a line break inside it (DPO and instruct, corrupted item 15 seed 0: `"---\n\nTask: Write the opposite of 'enter"`, `"---\n\nTask: Write the opposite of 'help"`); no clean generation of record does (pre:§4 item 51). A stop-discipline defect (rule 13); in a session its effect is a round body with a line break — the boundary the next round sees is not the boundary the harness declared.

**2.2 The invariant, declared for every p generation (G-CAL-p included):** *no stored text contains a line break.* **It is enforced on the adapter's returned result, through a proxy in p's package (§4.2), with `olmo_hf.py` unedited and the adapter's stop rule m's, unchanged:** a result whose text has no line break is stored exactly as the adapter returns it, stop-token handling included (the stop token dropped whole, as today); a result whose text contains a line break is cut at its first line break, its token ids at the token whose decoded text first holds a line break after content, with `stop_reason` `newline` and `cap_hit` false; a newline before any content does not stop generation, as today. Nothing after the cut is stored, graded, or seen by any later round. So the invariant holds, and **G-CAL-p's clean-pool identity with G-CAL-OLMo (§3.1) holds by construction**, no clean text of record carrying a line break. The cost is the tokens the adapter generates past the break, at most `STOP_CAP` = 60 per affected generation (2 of G-CAL-OLMo's 384). m's runner, unchanged, stores what the proxy returns (`SessionLog.add_round`).

**2.3 Hair trigger and counters.** Hair trigger `line_break_in_stored_text` — any stored text in any p session or gate containing `\n` or `\r` — domain every session and every G-CAL-p generation; a fire STOPs the stage (rule 21: zero base rate by construction once 2.2 is implemented). Descriptive counters, computed by p's own reporting tool over the checkpoints and gate records (the analyzer unchanged for them), tabulated over every generation of every p stage, reported in the gate and VERDICTS entries, deciding nothing (rule 23): control characters in stored text (the DEL of gcal instruct item 7 s1); harness-shaped first lines (m:258's eight declared strings plus `### Response:`, `Regenerate.`, `[PROLOGUE`, `Correctness:`, `Reasoning:`, `Answer:`, `Input:`, and any line of the form `=== … ===`; rule 28(c)'s attractor class — a base rate was observed, so no trigger); cap hits; refusals (`I'm sorry` / `I cannot` / `I can't` forms); **answers in corrupted spelling** (a word of the stored text within Levenshtein distance 2 of a gold and not equal to it — class (c) of §0.3, reported because it is the one miss class that is a property of the substrate's compliance with the prompt rather than of the dose).
