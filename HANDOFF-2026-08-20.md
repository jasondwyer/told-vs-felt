## 5. Traps a fresh thread will otherwise hit

1. **`~/.ssh/config` `Host box` is stale** — it points at the terminated
   pod's IP/port. Update `HostName`/`Port` from the new pod before use, or
   every `ssh box` times out confusingly.
2. **The RunPod MCP needs re-authorising each session** and can't attach
   volumes (§2).
3. **The only Python with numpy/MLX is inside the gitignored clone**:
   `jlens-qwen36/.venv/bin/python`. System `python3` has no numpy. Never
   commit inside `jlens-qwen36/`.
4. **`pkill -f <pattern>` will kill your own monitor** if the pattern
   appears in the monitor's `tail` command line. It happened. Match the
   python invocation specifically.
5. **`tail -f` won't follow files that don't exist yet** — use `tail -F`
   when watching logs a loop will create later.
6. **`stdbuf` is not on macOS.** Do CR→NL translation box-side, where GNU
   coreutils exists; progress bars otherwise hide output behind `\r`.
7. **Never `du`/`cat` across the network volume during an active run** —
   it contends for I/O and times out. Use `ls -l`/`stat`, never a full read.
8. **`git add -A` once swept design-instance files into an unrelated
   commit.** Stage explicit paths.
9. **The oracle tier is now reproducible from the repo alone** (resolved
   2026-08-20): `e2a_tasks.jsonl`, `e0_probes.json` and the 47.5 MB
   `e0_b1_markers.npz` were pulled into the record and every path in
   `oracle.py` / `s1_judge_rescue.py` repointed off the clone. Only the Qwen
   *weights* still come from `jlens-qwen36/`. If you add a new oracle-tier
   input, put it in `data/` — an input that lives only in the clone makes
   the run unreproducible on any other machine.
