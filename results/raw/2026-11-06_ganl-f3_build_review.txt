## Findings

**1. MINOR, close to MAJOR (`run_verdicts_f3`, the decision-(10′) check in V1; PIN-V2-12, N6).** The guard is weaker than the rule it encodes.
- It only checks that `POSTING-v1_outputs.of-record.json` exists (`is_file()`). `posting --posting v1` writes that file when it enumerates the table of record. That is the start of the v1 posting: before the PI's rewrites, and before C7's pass on the posted text.
- Only a PASS on the posted text writes `POSTING-v1_outputs.posted.json`; a FAIL writes nothing.
- Failure case: Code runs the of-record posting. While the PI is rewriting, `verdicts --unit Q-F3` passes V1 and writes Q-F3_VERDICTS.json. A Q-F3 outcome then exists before v1 posts, which A-m1:40 forbids.

- Fix: require `POSTING-v1_outputs.posted.json`, committed at HEAD (`env.committed`), with schema POSTING_OUT_SCHEMA, posting "v1", table_kind "posted" and bar.verdict "PASS". Reword PIN-V2-12 and N6 to match.

**2. MINOR (`run_posting_v2`; PIN-V2-4 and PIN-V2-21): nothing binds the v2 table of record. There is no v2 equivalent of PIN-40.**

## Findings on the delta

**1. NOTE (`main` for `ganl --out`): a quoted tilde path now lands inside the repo.**
- `main` now passes `--out` through `_cli_path`, which never expands `~`. So `run_ganl`'s own `expanduser()` no longer has anything to expand.
- Failure case: `ganl --out "~/x"` (quoted, or passed in argv by a script) now resolves to `<repo>/~/x` and creates a directory literally named `~` in the repo. Before the change it went to `$HOME/x`.
- Fix: call `Path(a).expanduser()` inside `_cli_path` before the absolute test, or leave a `~`-leading `--out` unresolved.

**2. NOTE (`run_not_run` with `--v2-closure`): what is left after the fix.**
- An absent `data/m/ckpt/{U}_campaign.json` is still read as "no session". That covers a checkpoint whose campaign file is not in this tree yet (still on the box) or was moved aside as `*.json.podchange-*` after a box change.
- `--campaign` is not checked to be this unit's checkpoint (`identity.unit`).
- A JSON object with no `sessions` list is refused with the "records sessions" message, which is the wrong reason.
- Suggestion: require the checkpoint to be present and committed, or a declared attestation when it is absent. Check `identity.unit`, and word the malformed case separately. None of this is a regression.

**3. NOTE (battery, F3R-READER-REFUSALS): the check asserts only that each case was refused, not why.**
- Each case changes one input from the passing default, so today the refusal can be traced to that input.
- Asserting the message would keep it that way, as F3P-REFUSALS already does with "PIN-V2-24" and "closed there first".

**4. NOTE (pre-existing, but now load-bearing): `.gitignore` ignores `data/mf3/verdicts/*.json`.** The rule is `/data/mf3/*` with no admit line for `verdicts/`, which `git check-ignore` confirms.
- `posting --posting v2` now reads `Q-F3_VERDICTS.json` and the no-first-read `Q-F3_NOT-RUN.json` for the table binding.
- The commit that first writes them will need an admit block, as PIN-25's practice has it.
