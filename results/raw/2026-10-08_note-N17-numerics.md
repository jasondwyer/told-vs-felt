## 6. The README paragraph (README-NOTE §6, beside N4(iv)'s)

**Qwen numerics.** Every Qwen result here comes from `mlx-community/Qwen3.6-27B-4bit` (Hugging Face revision `c000ac2c`), run with MLX 0.31.2 and mlx-lm 0.31.3 (the versions recorded by every Qwen artifact that names its model, the first committed on 15 August 2026; the environment's single install, dated at setup, and its single model snapshot are consistent with them throughout) on an Apple M4 Pro laptop. The checkpoint uses MLX's affine 4-bit quantization with a group size of 64 (one bf16 scale and one bf16 bias per 64 weights). Every linear projection in the language model is quantized, as are the token embedding and the output head; the norms, the depthwise convolution and the Gated DeltaNet decay parameters stay in bf16. The "custom kernel patch" is not our code. It is part of the MLX port we run, `jlens-qwen36` (WeZZard/jlens-qwen36 at commit `d788bc3`, Apache-2.0), kept as a gitignored clone inside the working copy and not part of the tag. At load time the port monkey-patches mlx-lm's Gated DeltaNet layers so that the model's 48 linear-attention layers can be differentiated for Jacobian-lens fitting: the recurrence becomes switchable between mlx-lm's fused Metal kernel and a pure-ops sequential loop, and the layer's forward is re-implemented inside a custom function with a hand-written Metal backward kernel (the port also installs a gradient-checkpointing wrapper, which, on a reading of the code, the custom forward bypasses). It changes how the recurrence is computed, not the weights or the quantization. Our adapter sets the cached decoding path to the ops loop (`set_inference_mode(False)`), recorded in the artifacts as `gdn_inference_mode: "ops (fused disabled)"`. Our own changes to the clone (a dependency pin, a bug fix in an ablation helper, edits to one example script, added modules and scripts) do not define or rebind any kernel. The record names two floors as numerics-shaped. First, with a steering vector as large as the residual norm at layer 48, a cached O(T) greedy decode diverged from the uncached O(T²) re-forward within the first 4 tokens of a 12-token check under a high-strain state, whichever kernel the cached path used, while a low-strain state of the same norm matched exactly. The record reads this as the high-strain state leaving the next token near an argmax tie, where small floating-point differences between the two computation paths flip it. The lab's rules therefore required the uncached path for greedy readouts under high-norm steering. Sampled steered generation was allowed on the cached path behind a next-token KL gate re-run for each direction family and dose; since September 2026 that gate licenses first-token reads only, and multi-token generation on the cached path needs its own token-identity check (the cached-generation disclosure says which runs this touches). Second, the cycle-2 conditioning gate failed at the scale of deterministic label geometry: the cosine between the conditioned label pair's fingerprint contrast and the state axis moved +0.021 between two counterbalanced, independently trained adapters, against a largest movement of 0.035 among 28 control label pairs. Both numbers are under 0.05, while the label-pair cosines themselves reach 0.15 and carry over from one adapter to the next. "Verified" in this repository never means compared against an unpatched or unquantized Qwen. The kernel gate compares the cached and uncached paths of the same patched 4-bit model with the same vector injected (for e2a, a maximum symmetric KL on the first response token of 7.11e-04 at dose 0.10 and 7.39e-04 at dose 0.20, against a bar of 1e-3; `data/e2a/g1_kernel_gate.json`). The choice-read check re-runs the identical unsteered forward on identical token ids; every e2a check measured a KL of exactly 0.0 (e2a's pre-registered bar was 1e-6; the refactored core requires exactly 0.0). The rule-26 oracle re-ran published measurements through the refactored code on the same model. No unquantized Qwen run is in the record: the planned bf16 subsample (S3, formerly g4) has not been run. The OLMo results ran at bf16 on PyTorch/CUDA without this port, so the 4-bit and patch caveats do not apply to them. The cached-path caveat does have an OLMo counterpart: multi-token cached generation diverged from uncached generation at SFT, DPO and Instruct (4, 2 and 1 of 14 test cases, greedy uninjected ones included; Base 0 of 14 in both runs), so every OLMo B-phase generation ran uncached.
